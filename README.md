# 坦克大战 Tank War

> 面向对象程序设计课程设计（2026）· Java SE + Swing 实现的经典坦克大战
> 支持 **单人闯关 / 双人合作 / 双人对战** 三种模式，三关卡递进难度，内置寻路 AI、道具系统、粒子特效与原创像素美术/8-bit 音效。

---

## 一、项目简介

本项目在经典 FC《坦克大战》玩法基础上进行了现代化重写与功能扩展。游戏采用 **固定步长游戏循环 + 状态机框架 + 分层架构**，严格遵循面向对象的封装、继承与多态，并综合运用了多种 GoF 设计模式、图搜索算法、多线程并发与对象池技术。代码共 **58 个 Java 类、约 6100 行**，全部使用英文标识符并配完整 Javadoc。

### 核心特性

- **三种游戏模式**
  - 单人闯关（SOLO）：保护基地鹰巢，消灭每关 20 辆敌方坦克。
  - 双人合作（COOP）：两名玩家并肩作战、共享基地与分数结算。
  - 双人对战（VERSUS）：两名玩家同台竞技，先击毁对方者胜。
- **三关卡递进**：每关地图布局、敌方编成不同，难度逐关提升。
- **智能敌方 AI**：巡逻 / 追踪 / 攻击三态有限状态机，BFS 追击玩家、A* 规划打通砖墙直取基地，具备视野遮挡（草丛隐蔽）、2 秒最后目击记忆与难度化追击名额。
- **道具系统**：加速靴、穿甲弹（星星）、护盾三类道具，注册式工厂创建、限时生效自动还原。
- **四类敌坦**：普通、快速、装甲、奖励坦克；击毁奖励坦克 100% 掉落道具。
- **完整表现层**：爆炸帧动画、火花/碎片粒子、屏幕震动、草丛遮挡、程序化矢量地形、原创 8-bit 音效与背景音乐。
- **数据持久化**：使用 `Preferences` 记录本地历史最高分。
- **双缓冲渲染**：`BufferedImage` 离屏绘制，画面无闪烁。

## 三、快速开始

### 方式 1：双击运行（推荐）

打开 `dist/` 目录，**双击 `run.bat`**（Windows）即可启动。
`dist/TankWar.jar` 为已打包好的可执行 JAR（图片、音效、关卡均已内置）。

### 方式 2：命令行运行 JAR

```bash
java -jar dist/TankWar.jar
```

### 方式 3：从源码运行（开发模式）

```bash
# 1. 编译（在项目根目录）
#    Windows PowerShell：
Get-ChildItem -Path src -Recurse -Filter *.java |
  ForEach-Object { $_.FullName } | Set-Content sources.txt
javac --release 17 -encoding UTF-8 -d classes '@sources.txt'

# 2. 运行
java -cp "classes;resources" com.tankwar.Main      # Windows
java -cp "classes:resources" com.tankwar.Main      # macOS / Linux
```

## 五、游戏元素

- **地形**：砖墙（可被子弹逐步打碎）、钢墙（仅穿甲弹可破）、草丛（可隐蔽其中）、河流（坦克不可通过、子弹可飞越）、基地鹰巢（被击中即失败）。
- **道具**
  - 🥾 **加速靴**：移动速度提升 1.6 倍，限时还原。
  - ⭐ **穿甲弹**：子弹威力翻倍，可击穿钢墙，限时还原。
  - 🛡 **护盾**：持续期间免疫一切伤害。
- **失败/胜利**：基地被毁或生命耗尽即失败；消灭本关全部 20 辆敌坦即过关，三关通关获胜。

## 六、系统架构

### 分层包结构

```
com.tankwar
├── Main                程序入口（EDT 装配、资源预加载、优雅退出）
├── constant            常量与枚举：配置、方向、地形、模式、难度、坦克/道具类型
├── model               游戏对象：GameObject / Tank / PlayerTank / AITank / Bullet / Base
├── map                 地图、关卡数据与加载、关卡管理
├── ai                  敌方大脑：三态 FSM、BFS/A* 寻路、视野工具
├── prop                道具抽象基类、三类道具、注册式工厂、生效管理器
├── core                游戏上下文、固定步长主循环、世界逻辑、HUD、计分
│   └── state           GoF 状态模式：菜单/进行/暂停/过关/失败 五状态
├── render              双缓冲面板、爆炸与火花、出生标记
├── input               意图(Intent)与输入管理器
└── util                资源加载、精灵缓存、音频、碰撞检测、对象池、崩溃日志
```

### 关键运行机制

- **固定步长主循环**：以 60 TPS（每秒滴答数）累加器驱动逻辑，渲染与逻辑解耦；掉帧时最多追赶 15 步，避免"螺旋死亡"，保证不同机器上游戏速度一致。
- **状态模式**：主菜单、进行、暂停、过关、失败五个状态各自封装进入/更新/绘制/输入处理，`GameContext` 作为状态拥有者，逻辑层不出现 `switch(state)`。
- **并发模型**：游戏循环线程、AI 周期决策调度线程（200ms 节拍）、性能监控线程协作；跨线程通过 `volatile` 字段与并发意图队列通信，调度线程均为守护线程，退出时统一关闭。

### 已运用的设计模式

| 模式 | 应用位置 |
| --- | --- |
| 状态模式（State） | 游戏五大状态的切换与行为分发 |
| 工厂方法 / 注册表（Factory + Registry） | `PowerUpFactory` 注册式创建道具，新增道具无需修改工厂，符合开闭原则 |
| 对象池（Object Pool） | 子弹对象复用，避免高频创建销毁带来的 GC 抖动 |
| 单例（Singleton） | 精灵缓存、音频播放器、资源加载器 |
| 策略（Strategy） | 不同坦克类型、难度参数与 AI 行为可替换 |
| 观察者风格事件 | 计分、特效随游戏事件解耦触发 |

### 核心算法亮点

1. **分步扫掠碰撞（防穿透）**：高速子弹在一帧内分步推进，并以"线段 vs AABB"检测，杜绝高速子弹穿过坦克/墙壁；坦克移动采用格线吸附 + AABB，贴墙滑动不卡死。
2. **BFS / A\* 双寻路**：开阔区域 BFS 求最短逼近路径；面对砖墙阻隔时 A* 以"打砖代价高于空地"规划可破坏路径，钢墙/河流视为不可达。
3. **三态有限状态机 AI**：巡逻（随机/格线行进）→ 追踪（目击玩家或受击后 2 秒记忆追击）→ 攻击（对齐开火、预判基地），并受视野与草丛限制；高难度下分配更多"主动追击名额"。
4. **刷怪调度**：刷怪队列 + 出生点占位重试 + 出生闪烁保护，同屏敌坦数量受控。
5. **子弹抵消**：相向飞行的子弹相遇互相抵消，还原经典细节。

### 美术与音频

- 全部精灵图由 **AI 生成像素原画** 后经程序化后处理（品红背景 flood-fill 抠图、统一 32×32 调色）得到；地形在运行时以矢量方式程序化绘制（砖纹、铆钉钢墙、水面波纹、草丛层次）。
- 音效与背景音乐由音频合成脚本程序化生成 8-bit 风格 WAV，无版权风险。
- 资源脚本位于 `tools/`（`process_assets.py` / `synth_audio.py` / `gen_levels.py`），可重复生成。

```bash
javac --release 17 -encoding UTF-8 -cp classes -d testclasses test/com/tankwar/TestRunner.java

```
